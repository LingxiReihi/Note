# 1 游戏脚本

## 1.1 C#运行时

### 1.1.1 Unity使用的脚本语言

C#是Unity使用的脚本语言，它属于高级语言。从开发效率角度来说C#高于C++，但运行效率远不及C++。

==Unity开发时仅仅使用了C#语法==，内部原理和`.Net`要运行时完全不同。在脚本开发中，Unity会通过编译器将==C#脚本编译为IL指令==，最终获得的所有IL指令会被编译到`Library/ScriptAssemblies/Assembly-CSharp.dll`文件中，每当代码有修改时，这个文件都会自动重新编译。

### 1.1.2 Unity跨平台原理

早期Unity在开发和打包运行均采用Mono方案（Mono运行时并非Unity开发的，而是一个开源跨平台的C#运行时解决方案），虽然Mono提供了跨平台解决方案，但许多的平台只提供了C++接口，并没有C#接口，这就导致了Unity没办法更好的与目标平台对接。

后来，Unity开发了==IL2CPP，用于在打包前将IL指令转换为C++代码，并在所有代码都转换成C++后统一打包==，这就为提升性能与多平台移植带来了不少便利。==Unity还接入了贝姆垃圾收集器，让C++也可以进行垃圾收集==（贝姆垃圾收集器是一个非精准、不分代的垃圾收集器 ，内部的大致原理是在监听`new`和`delete`关键字的同时记录引用关系，在收集垃圾的时候进行扫描并卸载无用的垃圾内存）。

## 1.2 C#与引擎交互

==Unity是一个标准的C++游戏引擎==，在运行模式下提供了`UnityEngine.dll`库和`UnityEditor.dll`库，随后再进一步调用Unity底层的C++核心代码。

如在C#中对一个Transform组件中的`position`属性赋值，在脚本文件中为：

```c#
transform.position = Vector3.zero;
```

因为这段代码为用户使用C#书写，所以UnityEngine.dll需要有一个C#的Transform类对象供用户调用使用，C#中Transform类中就有position的`get`和`set`方法：

```c#
[NativeHeader ("Configuration/UnityConfigure.h")]
[NativeHeader ("Runtime/Transform/Transform.h")]
[RequiredByNativeCode]
[NativeHeader ("Runtime/Transform/ScriptBindings/TransformScriptBindings.h")]
public class Transform : Component , Ienumerable
{
    ...
    public Vector3 position
    {
        get {
            get_position_Injected (out Vector3 ret);
            return ret;
        }
        set {
            set_position_Injected (ref value);
        }
    }
    ...
}
```

最终，`get`和`set`方法会通过`extern`绑定到C++中，此时传入的`Vector3`对象也会被传入引擎。

```c++
[MethodImpl (MethodImplOptions.InternalCall)]
private extern void get_position_Injected (out Vector3 ret);
[MethodImpl (MethodImplOptions.InternalCall)]
private extern void set_position_Injected (ref Vector3 value);
```

如下图，在C++的`Transform.cpp`中指定了新的坐标，引擎底层渲染系统就可以将场景中的所有渲染信息提交到CPU中，最后通过Shader的计算更新角色在屏幕上的位置。

在非运行模式下，可以直接在上面这个`Tranform`面板中直接修改各个属性的值，此时游戏中角色坐标会立刻发生变化。在编辑模式下，每个组件都对应着一个绘制类，如`Transform.cs`面板对应的就是`TransformInspector.cs`。这样每个组件都可以进行定制化绘制（如以下代码所示）。

```c#
namespace UnityEditor
{
    [CustomEditor(typeof(Transform))]
    [CanEditMultipleObjects]
    internal class TransformInspector : Editor
    {
        SerializedProperty m_Position;
        SerializedProperty m_Scale;
        TransformRotationGUI m_RotationGUI;
        ···
        public void OnEnable()
        {
            m_Position = serializedObject.FindProperty("m_LocalPosition");//通过Transform中真实的变量名找到序列化结果。
            m_Scale = serializedObject.FindProperty("m_LocalScale");
            
            if(m_RotationGUI == null)
                m_Rotation = new TransformRotationGUI();
            m_RotationGUI.OnEnable(serializedObject.FindProperty("m_LocalRotation"),EditorGUIUtolity.
                TrTextContent("Rotation",
                "The local rotation of this GameObject relative to the parent."));
        }
        
        public override void OnInspectorGUI()
        {
            ···
        }
        
        private void Inspector3D()
        {
            EditorGUILayout.PropertyField(m_Position,s_Contents.positionContent);//对属性进行绘制
            m_RotationGUI.RotationField();
            EditorGUILayout.PropertyField(m_Scale, s_Contents.ScaleContent);
        }
    }
}
```

在面板中我们看见的属性名为了便于我们编辑时理解，与其真实的属性名有所差距，我们只需要点开右上角菜单栏选择`Debug`，就可以看见他的真实属性（此时采用的为引擎默认绘制方法，而不是`TransformInspector.cs`绘制函数），效果如下图。
