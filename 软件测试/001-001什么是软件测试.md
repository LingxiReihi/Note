# 软件测试的概念

## 什么是软件

### 软件的概念

软件是控制计算机硬件工作的工具。例如微信、QQ、浏览器、操作系统等，都是软件。

### 软件的组成

一个软件由页面客户端-代码服务器-数据服务器三部分组成，他可能只包含其中一种或者两种。

### 软件产生过程

- **需求产生**：产品经理通过市场调研、用户描述需求，进行分析，设计用户需求。
- **需求文档**：产品经历通过用户需求设计需求文档，描述软件需要的需求。
- **软件设计**：按照需求文档，对软件界面、功能等进行分析设计。
- **编码实现**：由开发人员对软件进行编码实现，通过代码实现需求文档中的需求功能。
- **软件测试**：由测试人员对开发人员开发内容与需求文档对应功能进行测试，判断功能是否实现通过。若测试通过则进入下一阶段，否则记录bug返回到开发人员修复，并重复这一流程。
- **部署上线**：测试人员确定无误后，部署上线开始运营。

## 什么是软件测试

### 软件测试的概念

软件测试是使用**技术手段**验证软件是否满足使用需求。

软件测试覆盖整个生产流程，从需求文档到开发完成，无处不在。

### 软件测试的目的

软件测试的目的是减少缺陷（Bug），保证软件质量。

## 软件测试主要技能

- **功能测试**：功能测试是最基本的软件测试，保证软件基本界面、功能等的正常。例如登录注册是否正常、界面是否有不显示、获取的数据是否有错位等等。
- **自动化测试**：在测试登录等情况时，需要大量的数据测试，这个时候一条一条测试十分繁复，此时可以通过自动化脚本或自动化工具简化测试。
- **接口测试**：接口并非硬件上的接口，接口测试是使用代码和工具对服务端给出的api接口进行测试，判断参数和结果是否正常。
- **性能测试**：模拟大量用户对服务器进行访问，或模仿大型数据进行测试，验证运行性能，例如是否卡顿等等问题。

## 测试分类

### 按测试阶段划分

+ **单元测试：**针对源代码或某一最小独立功能单元的测试，确保其能正常运行。

+ **集成测试：**又称**接口测试**，针对模块之间的接口与交互进行测试，确保多个模块组合后能实现预期功能。

+ **系统测试：**对已经集成好的软件系统进行测试，验证系统功能，发现设计缺陷，评估非功能特性，保证系统稳定性。

  > 系统测试包括功能测试、性能测试、压力测试、安全测试、恢复测试、兼容测试。

+ **验收测试：**验收测试使软件上线前的最后阶段测试，用于确定系统是否满足合同或需求规格说明书的全部要求，包括性能、功能、文档与用户体验等，由用户进行执行测试。

  > 验收测试通常包含：正式验收测试、非正式验收测试（Alpha测试）、Beta测试

### 按代码可见度划分

+ **黑盒测试：**黑盒测试是一种只关注软件输入与输出，不考虑内部实现的功能性测试。
+ **白盒测试：**白盒测试基于源代码内部结构进行测试，也称为结构测试或逻辑驱动测试，要求测试人员了解程序内部逻辑并覆盖所有逻辑路径，如语句覆盖、判定覆盖、条件覆盖。
+ **灰盒测试：**灰盒测试是介于白盒与黑盒之间的测试方法，只掌握部分内部结构（模块交互、数据流、架构信息），并据此进行测试。（可以简单理解为接口测试）

## 质量模型

### 什么是质量模型

软件质量模型是一种将**软件质量结构化、可度量化**的框架，用于指导测试需求分析、测试设计、质量评估等活动。它通过“**质量特性 → 子特性 → 度量指标**”三层结构，使抽象的质量要求变得可验证。

### ISO/IEC 25010 现行八大质量模型

| 特性           | 典型子特性示例                       |
| -------------- | ------------------------------------ |
| **功能适用性** | 完整性、正确性、适合性               |
| **性能效率**   | 响应时间、吞吐量、资源利用率         |
| **兼容性**     | 共存性、互操作性                     |
| **易用性**     | 易理解性、易学性、易操作性、错误防御 |
| 可靠性         | 成熟性、容错性、可恢复性、可用性     |
| **安全性**     | 保密性、完整性、不可抵赖性、可审计性 |
| 可维护性       | 模块化、可分析性、可修改性、可测试性 |
| 可移植性       | 适应性、易安装性、可替换性           |

### 质量模型实际举例

#### 案例

1. 开发一款网络游戏（要求：10个主功能）
2. 游戏支持web（浏览器）端、App端
3. 游戏上线后预计每日20w用户在线

#### 功能性

| 需求        | 测试                                       |
| :---------- | :----------------------------------------- |
| 10个功能    | 功能数量为10个                             |
| 功能详情... | 功能正确实现<br>非法输入等错误实现情况处理 |

#### 性能

| 需求            | 测试                                           |
| :-------------- | :--------------------------------------------- |
| 每日20w用户在线 | 服务器每秒处理请求数<br>服务器硬件配置是否满足 |

#### 兼容性

| 需求         | 测试                                                         |
| :----------- | :----------------------------------------------------------- |
| 支持web和App | 不同浏览器内核是否可用（谷歌、Edge、火狐、苹果、欧朋）<br>不同操作系统是否可用<br>不同硬件环境下是否可用<br>是否会对其他软硬件产生影响等等 |

#### 易用性

界面是否美观简洁、操作是否友好流畅。

#### 可靠性

是否出现卡顿、无响应、死机崩溃等情况。

#### 安全性

重要数据是否加密、数据库应用等等是否安全。

#### 可移植性

软件迁移是否方便可行。

#### 可维护性

软件文档、脉络等是否清晰，维护是否方便。

## 软件测试流程

`需求评审 -> 计划编写 -> 用例设计 -> 用例执行 -> 缺陷管理 -> 测试报告`

**需求评审：**确保各部门需求理解一致。

**计划编写：**测什么、怎么测、谁来测。

**用例设计：**验证项目是否符合需求的操作文档。

**用例执行：**项目模块开发完成，开始执行用例文档实施测试。

**缺陷管理：**对发现的缺陷进行管理，重复修复->测试->修复一过程。

**测试报告：**实施测试结果的文档。
